# Lab1：先懂逻辑，再读实际语句

本文只解释本目录现有M1、M2、TB与脚本中的语句，是阅读附件，不是实验文档额外规定的独立交付文件。本文仅保留与当前源码相符的语句和信号说明，运行结果见验收说明。

## 1. 总体分工与一次写入

- [apb_slave_if.sv](apb_slave_if.sv)：M1解释APB请求，保存配置，控制对M2的访问，维护IRQ pending。
- [packet_sram.sv](packet_sram.sv)：M2按使能和word索引保存/读出位模式，不判断报文是否合法。
- [tb_lab1.sv](tb_lab1.sv)：TB模拟访问方与M3输入，连接DUT、驱动、观察和比较。

一次合法内存写：TB构造事务，interface在下降沿给SETUP，下一下降沿进入ACCESS；M1判断方向、地址和权限，M2在ACCESS上升沿保存数据，monitor检查写使能/索引/数据，随后通过读回确认。

数据出现在PWDATA输入端不代表已经保存。PWRITE决定读或写，PENABLE标记阶段；两者都不是主从触发器。写入还要满足合法地址、退出复位和无错误。

模块端口也不是顶层全局变量：M1的input声明接收端，TB/interface提供实际信号，通过`.PSEL(apb.PSEL)`等显式连接。左边是端口名，括号内是信号来源。

## 2. 地址判断与读写权限

[M1访问判断](apb_slave_if.sv#L79)使用：

```systemverilog
assign access_phase = PSEL && PENABLE;
assign write_access = access_phase && PWRITE;
```

它们是当前输入的组合结果，不保存历史。SETUP时PENABLE=0，所以没有写ACCESS。

[错误响应](apb_slave_if.sv#L86)的三个条件分别处理：

1. 既不属于CSR，也不属于有效内存word：地址未定义。
2. 是写且目标是RO：不允许软件改外部状态/结果。
3. 是写内存且busy=1：防止处理期间覆盖报文。

默认PSLVERR=0是每次组合计算的默认值，不是先保持一拍0再变1。合法内存读取不能因为“不是CSR”而报错；§6.3允许busy时仍读取当前内存。

错误响应与处理错误IRQ不同。PSLVERR响应本笔访问，退出ACCESS后恢复0；err_irq记录带错完成事件，可保持到软件W1C或复位。

## 3. 位切片：选哪些位，为什么这样选

```systemverilog
PADDR[1:0]
PADDR[4:2]
PWDATA[7:4]
```

- `[1:0]`取两位，要求00表示四字节对齐。
- `[4:2]`取三位，表示0~7的word索引。
- `[7:4]`取四位，保存CFG中的type_mask。

地址PADDR是12位，不是32位。PRDATA/PWDATA才是32位数据。

内存起点040的低五位为0，合法地址040+4N的`[4:2]`就是N。因此[M1地址输出](apb_slave_if.sv#L94)使用该切片。不过它持续随PADDR改变，只有内存地址有效且读/写使能有效时，M2才使用这个索引；不能仅看这根线非零就认为发生了操作。

## 4. 拼接：从高位到低位组成数据

```systemverilog
PRDATA = {31'b0, enable_o};
PRDATA = {24'b0, type_mask_o, 3'b0, algo_mode_o};
```

花括号这里表示位拼接：最左项放最高位。

- 第一条：31位0加1位使能，得到32位；enable放bit0，START的bit1读0。
- 第二条：24+4+3+1=32；mask放[7:4]，三个0放[3:1]，mode放[0]。

[M1读case](apb_slave_if.sv#L102)用12位地址选择哪一组32位返回值。默认PRDATA=0补全组合路径，避免锁存器；合法内存分支会用M2值覆盖它，因此该默认值不会初始化未写过的SRAM。

未使用位读0与非法地址不是同一件事：有效寄存器里的保留位读0，但未定义目标应返回错误响应。非法读的PRDATA具体值没有被规格规定，错误测试只要求PSLVERR正确。

## 5. 枚举、类型和结构体

[TB的类型定义](tb_lab1.sv#L2)把地址命名为apb_address_t、数据命名为apb_data_t。typedef是类型别名，不新建一个变量。

```systemverilog
typedef enum logic {APB_READ = 0, APB_WRITE = 1} apb_direction_t;
```

enum给值命名；底层是一位logic，与PWRITE对应。CSR地址枚举中的CFG是地址004的名字，不是一个存储CFG内容的寄存器。

```systemverilog
typedef struct packed {
  apb_direction_t direction;
  apb_address_t address;
  apb_data_t data;
} apb_transaction_t;
```

三个字段实际送到PWRITE/PADDR/PWDATA。packed将1+12+32位组织为可整体比较的45位记录，monitor可将ACCESS记录与SETUP记录比较。

这是“一笔APB访问”的记录，不是SRAM中的报文格式。Lab1没有借此实现包头解析算法。

### 拼接与赋值模式不同

```systemverilog
request = '{direction:APB_WRITE, address:address, data:data};
```

这里是带单引号的赋值模式：冒号左边是struct字段，右边是调用参数，按名字填值。不等同于没有单引号的位拼接。

类型和interface集中定义在TB文件中，所以不需要独立package。Questa日志里的tb_lab1_sv_unit是文件级类型的内部编译组织，不是新增的手写Lab2源码。

## 6. 类型/宽度转换并不自动验证合法性

```systemverilog
proc_rd_addr = 3'(index);
return 12'h040 + 12'(index * 4);
```

`3'(...)`、`12'(...)`调整结果宽度。index是int，但端口/地址只有3/12位；代码通过0~7循环保证索引合法，不依赖转换来检测越界。

```systemverilog
apb_direction_t'(apb.PWRITE)
```

这是转换到枚举类型，让采样记录的direction字段类型一致。它不是随机生成新方向，也不会把任意未知值变成正确请求。

## 7. automatic function/task：生命周期与时间不同

[packet_address](tb_lab1.sv#L114)只根据index计算地址，没有等待时钟，适合function。[transfer](tb_lab1.sv#L22)和reset_dut包含边沿等待，必须用允许耗时的task。

automatic使每次调用的参数/局部变量独立；不是“自动调用”，也不是并发仲裁。当前APB激励串行调用，共用一个接口。

function不能用等待时钟或时间延迟推进仿真；task可以等待，也可以不等待。本代码check_value是无延迟task，目的是复用检查接口，不代表所有task都必须耗时。

## 8. 阻塞赋值、非阻塞赋值与采样

- TB的`PADDR = request.address`是阻塞赋值，在当前进程立即完成，再执行后续语句。
- RTL的`enable_o <= PWDATA[0]`是非阻塞赋值：本沿计算右侧，安排NBA阶段更新左侧。
- `PADDR <= 12'h05C`出现在条件表达式中时，`<=`是“小于等于”比较，不是赋值；根据语法位置区分。

在[M1控制寄存器](apb_slave_if.sv#L119)中，先安排enable更新、再判断enable，判断仍用旧值。因此先CTRL=1再CTRL=3可以明确使能并启动；写CTRL=2还会要求清enable，不能当作“不影响其他字段，只写START”。

### 两种等待/阻塞不要混淆

`@(negedge PCLK)`暂停当前task，时钟always和monitor仍继续，不是整个仿真停止。赋值的“阻塞”与总线等待状态不同：本实验PREADY固定1，没有背压；驱动若见到PREADY不是1便报告违反规格，而不是实现通用等待循环。

### 为什么有的检查等1ns，有的不能等

- APB响应在ACCESS接收上升沿立即采样，与真实主机看到的边沿前值一致。若等NBA之后，可能读到本沿刚更新的另一状态。
- M2同步读输出、START脉冲清除要观察本沿更新结果，因此相关检查在上升沿后`#1ns`。
- proc读的另一个`#1ns`位于下降沿之后、尚未到上升沿，用来确认数据不能提前变化。
- irq_cycle在PCLK上升沿用`<=`发布done/错误，`#1ns`后、下一上升沿之前检查IRQ_STA读数据与irq_o；这时saved仍为0。下一沿后再检查saved，区分组合响应和保存。

这些延迟都在TB中，不在RTL中；它们只给仿真非阻塞更新和组合计算留出稳定采样时间，不证明物理路径无毛刺。

## 9. M2的数组、独立读口与复位

```systemverilog
logic [31:0] mem [0:7];
```

每个元素32位，共八个元素，总容量256bit。每个word保留四字节位模式；报文的字节解析由M3负责。

[M2时序块](packet_sram.sv#L19)用三个独立if：写许可有效时更新数组，两个读许可各自更新各自输出。因此读口可以同拍服务，不是else-if互斥选择。

使能为0时未安排新值，读输出保持旧值；不是自动清0。复位只清两读输出，没有遍历数组；测试先写后读，不能把未写数组当成复位0。

所有`<=`右侧使用本沿前状态，因此同地址同拍读写取旧数据。本实现采用read-first，文档未规定这个冲突策略，基础用例不依赖它。

## 10. START与IRQ：事件和状态不能混为一谈

START表示一次启动动作：每拍默认清0，合法控制写安排为1，下一拍无新启动便归0。输出需要一拍寄存，但CTRL.start不保存持久1，软件读回0。

[M1中断路径](apb_slave_if.sv#L151)用`done_i && !previous_done`识别新的完成。在本目录独立TB中，done_i由TB信号驱动；真实M3在Lab3/4顶层集成中使用，其done_o输出端口通过done连接信号接到M1.done_i输入端口，中间不再增加寄存器。§8.2对错误IRQ也要求同一次新done、任一处理错误和err使能，错误单独变化不能独立触发。

done_irq_saved/err_irq_saved是两位保存寄存器，记住已经发生且未清除的中断。done_irq/err_irq不是另一组保存寄存器，而是当前可见值：

```systemverilog
assign done_irq = PRESETn && (done_irq_saved || (done_i && !previous_done && done_irq_en_o));
assign err_irq = PRESETn && (err_irq_saved || (done_i && !previous_done && err_irq_en_o && error_any));
```

以完成位为例：退出复位后，保存位为1，或者done为1、previous_done为0且完成使能为1，done_irq就为1。IRQ_STA读回选择这个值，irq_o对两位可见值做OR，所以M3发布完成后不用再等一个PCLK沿。下一沿saved接收可见值、previous_done接收done；新事件条件退出后，由saved继续保持。

W1C时，[保存块](apb_slave_if.sv#L155)为每一位选择`可见值 && !写入位`：写0接着保存，写1清除。用if/else明确二选一，不靠同一过程内先清0、后置1的顺序。上一周期已可见事件的提交不能盖过W1C；如果真正的新完成在本沿NBA之后才出现，previous_done采到的仍是0，新完成仍从组合路径可见，并在下一沿保存。

关闭使能不直接清saved，done持续高也不会不断触发。IRQ_EN和新完成都在同一PCLK沿后更新时，组合判断使用更新后的使能。当前M3会将done与结果/错误保持到下一合法启动或复位；两次完成之间done低电平须被PCLK采样，不保证异步窄脉冲。

## 11. 未知值比较与真正的失败

`logic`保留0/1/X/Z；正常期望值应明确。[check_value](tb_lab1.sv#L119)现在同时拒绝actual/expected的未知位，再用`!==`比较。

`!==`不是通配比较：实际X与明确0不相等，但X与X本来可以完全相等。因此不能只用一句“!==遇X总失败”解释它。若参考值自己没初始化，也应当失败，而不是把两个未知值当正确。

monitor检查实际总线与M1送往M2的写接口，期望word数据由刺激生成，不读取DUT内部mem来制造黄金值。错误响应检查与数据比较各自明确，错误访问不再强制未规定的读数据值。

## 12. 脚本负责运行，不属于硬件逻辑

- [compile.do](compile.do)：按两份RTL、TB顺序编译，类型/interface在TB文件内先定义后使用。
- [run.do](run.do)：从当前目录找文件，自动编译、设置seed、按RUN_ID和测试名/seed记录日志与WLF、检查完成标志；已有同名输出时拒绝覆盖。
- [batch.do](batch.do)：宏错误返回非零，不把$finish/$fatal都当成功。
- [wave.do](wave.do)：只配置显示分组；删除wave显示项不是删除源码或WLF。
- [Makefile](Makefile)：提供smoke/regress和单项入口，子命令失败会传到父命令。regress固定运行seed 1、123、2026；指定一次完整回归的seed需用`make run TEST=regress SEED=值`。

运行测试时，compile.log与run.log位于logs/RUN_ID/测试名_seed/，波形位于waves/RUN_ID/测试名_seed.wlf。只执行`make comp`时，控制台日志仍使用RUN_ID，但compile.do未收到测试日志目录，另建logs/compile_工具计时值/compile.log；两种入口的编译日志路径不能混为一谈。

`quit -sim`卸载旧设计而不退出GUI；`onfinish stop`让脚本检查test_done。完成标志用二进制读取，避免工具把单比特十进制显示为-1造成误判。GUI前置步骤是进入try/lab1目录，脚本不声明支持任意工作目录。
